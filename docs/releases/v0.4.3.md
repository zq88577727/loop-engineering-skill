# v0.4.3 Convergence Safeguards

Release date: 2026-08-03

## Summary

This patch release tightens three behaviors observed in independent use of the
Loop Engineering workflow pack. It does not add a new framework layer.

## Fixes

- Limit low-risk, reversible work to at most one clarification turn, then
  proceed with labeled conservative assumptions.
- Require the lowest-complexity delivery form that satisfies acceptance; do not
  add a server, build system, database, model, or framework without a named
  acceptance need.
- Require Final State Readback before PASS, STOP, or DEMO_FREEZE so README,
  `state/triage.md`, `state/next.md`, and the final response agree.
- Add the `simple-demo-convergence` behavior scenario and validate semantic
  evidence without depending on one exact Markdown layout.

The existing Project Outcome Gate, `state/next.md` candidate rule, loop budget,
ship/stop behavior, and human gate remain part of the workflow pack.
